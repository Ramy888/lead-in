      Insights

      What comes from where

      Qloo says
      Audience overlap between shows, each show's aggregate audience skew (age, gender), and titles that share an audience with your library. These are aggregate affinities, never facts about an individual viewer.
      Our read
      Who typically watches in each daypart, how a show's skew fits that, the cut-off for a weak handoff, and the scheduling itself. These are Lead-In's assumptions, open to argument.
      TMDB
      Episode runtimes, which set slot lengths (runtime plus about 12% ad load, rounded up to half hours).

      How the day is built

      1. Resolve each title to a Qloo entity. Ambiguous titles ask you to choose.
      2. Get each show's audience skew and score its fit for every daypart.
      3. Build a one-way overlap matrix: how much of show A's audience stays for show B.
      4. Search for the 24h loop with the best total of handoffs plus daypart fit. Every show airs at least once (when the library fits), and runs of the same show are capped.
      5. Flag weak handoffs and dayparts the library serves poorly, then ask Qloo which titles would fill them.

      Qloo results are aggregate audience affinities, never facts about any individual viewer. No personal data is sent to Qloo.

      TV data from TMDB. This product uses the TMDB API but is not endorsed or certified by TMDB.
